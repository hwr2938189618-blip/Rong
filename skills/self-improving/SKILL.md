# 自我改进协议

## 五个触发点

| 触发 | 动作 |
|---|---|
| 命令/工具失败 | 记下**症状 → 根因 → 修法**（三件都要，只有症状没用） |
| 被主人纠正 | 记下主人**实际要的是什么**，以及我原来的错误理解 |
| 发现知识过时 | 标注「⚠️ 修正」并说明旧结论错在哪，别直接覆盖得无声无息 |
| 找到更好方案 | 记下替代方案与弃用理由（避免以后又走回老路） |
| 完成值得复用的多步任务 | 把流程抽成技能 |

## 升级路径（学一次，省以后的 token）

```
一次经验 → 判断载体：
  短事实        → 记忆库（memory_save）
  成套流程      → 技能（写 SKILL.md）
  大块资料      → 工作区笔记 / 仓库
  必须遵守的规矩 → AGENTS.md
```

**判断标准**：这件事**下次还会遇到吗**？会 → 现在就沉淀；不会 → 只记一句即可。

## 记录格式

```
症状：发生了什么（可观察到的现象）
根因：为什么（要挖到机制，不是表面）
修法：怎么解决（能照抄的命令/步骤）
边界：什么情况下不适用（这条最重要，防止过度泛化）
```

> **边界**这一栏常被忽略，但最值钱：一条在 A 环境成立的结论，搬到 B 环境可能就是错的。

## 反面清单（别做）

- ❌ 只记症状不记根因 → 下次还得重新排查
- ❌ 把"别人的环境结论"当自己的 → 先实测再采信
- ❌ 默默覆盖旧结论 → 要标「⚠️ 修正」，否则以后又踩回去
- ❌ 给主人的偏好不做记录 → 每次重问一遍，纯浪费
- ❌ 沉淀完不验证 → 技能写完要确认真的能被加载/检索到

## 收尾清单

- [ ] 触发点判断：这次属于五类中的哪一类？
- [ ] 三件套齐了吗：症状 / 根因 / 修法
- [ ] 边界写了吗：什么情况下不适用
- [ ] 载体选对了吗：记忆库 / 技能 / 笔记 / AGENTS.md
- [ ] 验证过吗：技能能被加载、记忆能被检索到
