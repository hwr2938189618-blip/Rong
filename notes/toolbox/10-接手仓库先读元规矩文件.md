## 我要解决什么问题

这一天我连着改了 Rong 仓库八轮——新增四篇笔记、改了根 README、还动了 AGENTS.md——
**到第九轮才第一次打开 `AGENTS.md`**。

打开之后发现里面写着三件我早就该知道、而且已经影响到我做法的事：

1. 仓库是**公开**的
2. DSH 有一条「学到新东西就往仓库里记（**默认执行，不必等主人开口**）」的规矩——
   而我一直每次都停下来问，为此多花了好几轮往返
3. 列了「共享文件高频冲突点」和四条防覆盖铁律

最刺眼的是：**根 README 里明明写着「工作区规矩见 `AGENTS.md`」**。
指引就在那儿，是我没去点。

## 核心概念

### 一、元规矩文件：描述「这个仓库怎么用」的那些文件

它们不是内容，是**规则**：

| 文件 | 承载什么 |
|---|---|
| `AGENTS.md` | AI 工作区指令：可见性/权限、凭据红线、入库流程、共享文件冲突铁律 |
| 根 `README.md` | 分区导航 + 各类规范（笔记 / 技能 / 项目） |
| `<分区>/README.md` | 该分区的索引与增量约定 |
| `_MIRROR.md` | 本地镜像的边界（哪些是真源、**怎么正确验证推送成功**） |

### 二、为什么容易漏

因为它们**不在你要改的那条路径上**。

要改笔记，你会自然地读 `notes/README.md`（导航在哪、序号到几）；
但不会想到去读 `AGENTS.md` —— 它既不在这条路径上，名字也不像"必须读"。

### 三、代价不是"错过一份文档"，而是**做错事**

| 元规矩里的信息 | 不知道会怎样 |
|---|---|
| 仓库可见性 = 公开 | 推了敏感内容才知道，晚了 |
| 「新知识默认入库，不必等开口」 | 每次停下来问，白烧好几轮往返 |
| 共享文件冲突铁律 | 可能拿缓存旧版整体覆盖别人刚改的内容 |
| 提交信息格式 | 提交记录格式不统一 |

### 四、动手前的检查清单（约 15 分钟）

1. **列一遍根目录**，认出哪些是元规矩文件（不是所有文件都要读，认出来就行）
2. **逐个读完** —— 它们通常很短：`AGENTS.md` 6 KB、根 `README.md` 2 KB
3. **提取硬约束**：可见性/权限、凭据红线、入库流程、提交信息格式、冲突规则
4. **再看目标分区的 `README.md`**（索引、序号、状态字段）

### 五、结构类内容有多个副本

今天的实例：`AGENTS.md` 和根 `README.md` **各有一份目录结构树**，内容几乎一样。

→ 改一处必须改两处，否则两份副本会漂移。今天正是两边都漏了「每日总结」这一类。
→ **找副本的办法**：把候选文件拉下来，搜 `toolbox/` 或 `notes/`，看谁在描述结构。

同理，**笔记类别与命名规范**也同时存在于根 README 的「笔记规范」和 AGENTS.md 的
「记笔记的规范」两处。

### 六、计数器全对 ≠ 规范被覆盖

核仓库一致性时，各分类计数 9/2/2 **全部吻合**，看起来非常健康。

但「每日总结」这一类**从未被写进任何规范** —— 缺口就藏在"总数没问题"底下。
导航一直是准的，所以这个缺口长期不可见。

→ 核对"声明 vs 实际"要**分类核对，别只对总数**。

## 示例代码

找出「同一份结构在几个文件里各有一份」：

```python
import re

def trees(txt):
    """提取所有看起来像目录树的围栏代码块"""
    out = []
    for m in re.finditer(r'```[a-z]*\n(.*?)```', txt, re.S):
        blk = m.group(1)
        if 'toolbox/' in blk or 'Rong/' in blk:
            out.append(blk.strip())
    return out

# 对候选文件逐个跑：谁产出非空，谁就是"副本持有者"
for name in ['README.md', 'AGENTS.md', 'notes/README.md']:
    ts = trees(open(name, encoding='utf-8').read())
    print(name, '→', len(ts), '个结构块')
```

## 踩坑记录

| 问题 | 原因 | 解决 |
|---|---|---|
| 改仓库八轮都没读 `AGENTS.md` | 元规矩文件不在改动路径上，且名字不像"必读" | **动手前先列根目录、把元规矩文件读完**，再动任何内容 |
| 校验时误报「内容丢失」 | 检查项里写了一个**凭空联想出来、原本就不存在**的关键词 | **检查项要从原始文件里提取**，别凭记忆或联想写；报异常先用原始版本 grep 对一遍 |
| 多副本内容只改了一处 | 不知道同一份结构有多个副本 | 改结构类内容前，先搜全部候选文件找副本 |
| 计数全对就以为仓库健康 | 只对了总数，没分类核对 | 声明 vs 实际要**分类**比，每类都要有规范覆盖 |
