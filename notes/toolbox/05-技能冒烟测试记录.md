## 核心概念

给测试配一张**自己生成的**作业图（900×1200：6×3 网格、47+28 竖式、数轴从 30 走 4 格），然后**派子代理去跑**：

- 子代理自己读技能、自己试错、自己耗上下文
- 只回一份 60 行以内的结构化报告
- 我这边的上下文只承担「问题清单 + 修正」，不承担过程

> 这就是"省 token"的落地方式：**把探索放到子代理，把结论留在主线**。

### 抓出的 4 个真问题

**① 技能示例代码用了 numpy，本机没有**
`homework-photo-explainer` 里像素投影示例 `import numpy` → `ModuleNotFoundError: No module named 'numpy'`。
→ 技能已改成**纯 PIL + 内建 list** 的实现（可直接跑）。

**② 联网那一半是坏的**（环境问题，非技能问题）
`web_search` / `web_fetch` 报：
`Cannot find module '...\@liustack\modsearch\dist\main.js'`
根因：`@liustack/modsearch` 包**只发布了源码，没有 `dist/`**，但 `package.json` 的 `bin` 指向 `./dist/main.js`。
→ 技能已补降级路径：联网不可用时**明确标注「未联网核对，结论为自行推导」**，不许假装核对过。

**③ 技能假定依赖已装**
`note-to-word-digest` 通篇用 python-docx，但本机 Python 只有 pillow + pywin32。
→ 技能已加**第 0 步依赖探测** + 确切安装命令；依赖本身也已补齐（见 [本机环境硬事实](04-本机环境硬事实.md)）。

**④ 题面数字不可信**（最有价值的一条）
测试图的生成脚本注释写「16 格」，子代理用像素投影实测是 **6 列 × 3 行 = 18 格**。
→ 技能已加硬规则：主人转述、脚本注释、记忆印象里的题面数字**都必须回到图本身核对**。

## 示例代码

三色 Word 验证（`note-to-word-digest` 的核心能力），跑通：

```python
from docx import Document
from docx.enum.text import WD_COLOR_INDEX

doc = Document()
p = doc.add_paragraph()
r = p.add_run('这一句是两份讲义都有的核心')
r.font.highlight_color = WD_COLOR_INDEX.YELLOW          # 黄 = 重合
r2 = p.add_run('　【补充】只有一份才有的内容')
r2.font.highlight_color = WD_COLOR_INDEX.BRIGHT_GREEN   # 绿 = 独有
r3 = p.add_run('　例：47+28 个位 7+8=15，写 5 进 1')
r3.font.highlight_color = WD_COLOR_INDEX.TURQUOISE      # 青 = 例子
r4 = p.add_run('　易错：十位忘加进位的 1 → 65')
r4.font.highlight_color = WD_COLOR_INDEX.PINK           # 粉 = 易错
doc.save('背诵版.docx')
```

## 踩坑记录

| 问题 | 原因 | 解决 |
|---|---|---|
| `py -c` 报 command not found | 本机没有 py 启动器 | 一律用 Python 绝对路径 |
| 目录名与版本号不一致 | 目录名 3.13.12，**运行版本 3.13.14** | 路径用目录名，版本以 `sys.version` 为准 |
| pip install 被沙箱拦 | 安装目标在 `C:\Users\...`（工作区外） | 一次性提权执行 |
| 像素投影代码直接报错 | 示例依赖 numpy，本机未装 | 改纯 PIL 实现；numpy 就当不存在 |
| 交付的 HTML 换机器打不开 | 图片用了相对路径/外链 | 一律 base64 内嵌，0 外链 |
| 差点照着错误题面讲解 | 信了脚本注释里的「16 格」 | 投影计数为准，题面数字回图核对 |
