# 应用自带缓存的孤儿判定

> **日期**: 2026-10-03
> **标签**: #磁盘清理 #技能库 #插件缓存 #审计方法 #决策
> **状态**: 🟢 已整理

## 我要解决什么问题

工作环境里堆了两类"看着就该清掉的东西"：

- `~/.workbuddy/plugins/cache/` 下 39 个旧版 `5.5.6-*` 目录，加一个 `weixinpay/1.6.109`，合计约 27.8 MB
- 36 个技能里有 3 个"明显不对劲"：描述为空、描述串味、平台不适用

直觉反应是清掉。但真去核影响之后，**一条都不该动**。这篇记的是中间那层判断——怎么从"看着像残留"走到"确定是残留"，以及为什么"确定是残留"仍然不等于"该动手"。

## 核心概念

### 一、判断孤儿：靠台账引用计数，不靠版本号大小

**"目录名里带旧版本号"只是线索，不是证据。** 应用可能仍会读旧目录（回滚、兼容），也可能那个插件早卸载了但旧版还留着——两种情况处理方式完全不同。

唯一可靠的办法：去应用**自己的安装台账**里数引用次数。

WorkBuddy 的几层持久化：

| 对象 | 路径 | 体量 | 性质 |
|---|---|---|---|
| 用户技能 | `~/.workbuddy/skills/` | 7.4 MB | 真源目录 |
| 插件缓存 | `~/.workbuddy/plugins/cache/<来源>/<插件>/<版本>/` | 90 MB | 按版本分目录 |
| **插件台账** | `~/.workbuddy/plugins/installed_plugins.json` | 17 KB | **权威引用表** |
| 技能缓存① | `~/.workbuddy/.skill-list-cache.json` | 70 KB | 扫描缓存 |
| 技能缓存② | `~/.workbuddy/storage/*/scoped/*/skills-installed-store.json` | 449 KB | 按 cwd 分作用域的缓存 |

做法就是把版本号当字符串，在台账里数出现次数：

```python
import json
s = json.dumps(json.load(open(ledger, encoding='utf-8')), ensure_ascii=False)
for v in ['5.5.6', '5.6.2', '1.6.109', '1.6.110']:
    print(v, s.count(v))
```

实测结果：

| 版本号 | 台账命中 | 判定 |
|---|---|---|
| `5.5.6`（39 个目录） | **0 次** | 孤儿 |
| `5.6.2`（现行） | 82 次 | 在用 |
| `1.6.109` | **0 次** | 孤儿 |
| `1.6.110`（现行） | 2 次 | 在用 |

### 二、第二重判据：旧版是否每个都有新版对应

命中 0 次只说明"台账没引用"。还要再问一句：**这是"升级残留"，还是"这个插件已经卸载了"？**

- 39/39 个 `5.5.6-*` 都有同名 `5.6.2-*` → 纯升级残留，删了不影响任何插件
- 若某个旧版**找不到新版对应** → 那是"插件已卸载、旧目录没清"，要单独判断该插件还要不要装回来

### 三、缓存 / 真源 / 注册表：三者判断标准不同

| 类型 | 例 | 删错的后果 | 处置 |
|---|---|---|---|
| **缓存类** | `plugins/cache` | 可重新下载，能自愈 | 风险低 |
| **真源类** | `skills/` | 真没了，且可能有误触发风险 | 谨慎 |
| **注册表/状态** | `.skill-list-cache.json` | — | **不要手工改**；带 `savedAt`/`fetchedAt`，刷新自愈 |

### 四、技能的"平台不适用"是隐形坑

技能 frontmatter 会自述平台要求：

```yaml
metadata: {"clawdbot":{"requires":{"bins":["osascript"]},"os":["darwin"]}}
```

这在 Windows 上永远跑不了。**但它不是安静失效**——它会带着一副正常可用的描述出现在技能列表里，模型可能真去调 `osascript`，然后失败。

→ **"会误触发的死技能"比"纯占空间的孤儿目录"更该处理**：前者产生错误行为，后者只占磁盘。

### 五、⭐「不完美」≠「要处理」

本文最值钱的一条。

审计一共列出 **12 条问题**，逐条核影响后 **0 条值得动**。因为影响分三个等级：

| 等级 | 表现 | 该不该动 |
|---|---|---|
| **零功能影响** | 纯占磁盘（27.8 MB 孤儿缓存） | 不动——收益是磁盘空间，风险是句柄冲突/结构破坏 |
| **惰性** | 描述空/坏的技能：不误触发、不报错、不占运行时开销 | 不动——只是"装了没发挥作用"，只在**确实要用**时才有价值 |
| **真实摩擦** | 会误触发的死技能（osascript 那条） | 观察——优先级最高，但依然很轻 |

关键推理：**27.8 MB 在一台正常容量的盘上等于噪声**，而"动它"要付出"App 运行时句柄冲突、缓存目录被破坏"的不确定风险。**收益确定且微小，风险不确定 —— 不划算。**

而"描述坏掉的技能"本质是**使用需求问题，不是技术问题**：修好它只在你要用 ima / 搜索引擎时才有价值。→ 内容留着，等真要用再修那一行。

## 示例代码

审计脚本骨架：

```python
import os, re, json

base = os.path.expanduser('~/.workbuddy')

# 1) 列出待判定的版本化目录
cache = os.path.join(base, 'plugins', 'cache', 'workbuddy-builtin')
targets = []
for plugin in os.listdir(cache):
    d = os.path.join(cache, plugin)
    if os.path.isdir(d):
        for ver in os.listdir(d):
            targets.append((plugin, ver))

# 2) 台账引用计数
ledger = os.path.join(base, 'plugins', 'installed_plugins.json')
s = json.dumps(json.load(open(ledger, encoding='utf-8')), ensure_ascii=False)
for plugin, ver in targets:
    if s.count(ver) == 0:
        print(f'孤儿候选  {plugin}/{ver}  (台账命中 0)')

# 3) 技能 frontmatter 体检
sk = os.path.join(base, 'skills')
for name in sorted(os.listdir(sk)):
    p = os.path.join(sk, name, 'SKILL.md')
    if not os.path.isfile(p):
        continue
    body = open(p, encoding='utf-8', errors='ignore').read()
    m = re.match(r'^---\r?\n(.*?)\r?\n---', body, re.S)
    fm = m.group(1) if m else ''
    d = re.search(r'^description:\s*(.*)$', fm, re.M)
    val = d.group(1).strip() if d else ''
    flag = []
    if not val or val in ('""', "''"):
        flag.append('描述为空')
    if 'osascript' in fm or 'darwin' in fm:
        flag.append('平台不适用')
    if flag:
        print(f'技能 {name}: {"/".join(flag)}')
```

⚠️ 别用"取不到技能名就回退用目录名"——内置 SKILL.md 的 `name` 字段位置会异常，兜底会取到版本号字符串。

## 踩坑记录

| 问题 | 原因 | 解决 |
|---|---|---|
| 把 `description: \|-` 的块标量误判成"YAML 缩进写坏、解析器拿到符号" | 只看自己的解析输出，没读原文 | **元数据问题必须读原文**。块标量是合法的，那条真正的问题是**内容填错**（写成了别的领域），描述其实一直生效 |
| 一度把 27 个内置技能误报成"跨来源重名" | 统计重名时用"取不到 name 就回退用目录名" | 兜底回退会取到版本号字符串。**先人工抽查 frontmatter 再下结论** |
| 认为"清单都列出来了"就该顺手清掉 | 把审计产物当成了待办 | 出清单时**每条都要带影响评估**，否则会把"不完美"当成"要处理" |
| 想清理时没注意 App 正在运行 | — | `tasklist` 可见 5 个 WorkBuddy.exe 进程；缓存目录可能被句柄占用，**优先搬移到隔离区而非硬删**，被占用的逐条跳过并报告 |
| 以为"删了目录就干净了" | 没注意还有两层注册表缓存 | 技能目录之外还有 `.skill-list-cache.json` 和 `skills-installed-store.json`。但它们是缓存会自愈，**不要手工改** |
| 想卸载技能却发现市场"只能装不能卸" | — | WorkBuddy 的 `skill-marketplace-skill-installer` 只有 install、没有 uninstall，清技能只能手动删目录 |
