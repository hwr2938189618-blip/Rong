## 核心概念

### 1. 内容是谁渲染的，决定第一步看哪里

`GET /` 返回的是空壳（只有 `<div id="app">` 和一个 `<script>`），内容全靠 JS 拼。所以「看 HTML」什么都不剩，**逻辑全在 `app.js` 里**。

> 任何站第一句都问：内容是谁渲染的？服务端渲染 → 看 HTML；前端渲染 → 看 JS。

### 2. 混淆的字符串表：不逐行读，先还原

`app.js` 长这样：一堆 base64 字面量放进 `_0xa` 数组，配一个 `_0xd(i)` 解码函数，整体包在 IIFE 里（所以控制台里 `_0xa` 拿不到）。

还原办法（浏览器控制台或 Node 都行）：

```js
var a = [ /* 复制 _0xa 的内容 */ ];
function d(i) {
  var b = atob(a[i]);
  var s = '';
  for (var k = 0; k < b.length; k++) s += '%' + ('00' + b.charCodeAt(k).toString(16)).slice(-2);
  return decodeURIComponent(s);   // 这三步是为了还原 UTF-8 中文
}
a.forEach((_, i) => console.log(i, d(i)));
```

还原出来直接就是**接口清单**（`/api/me`、`/api/login`、`/api/register`、`/api/logout`、`/api/notes`）加**角色名**（`guest` / `admin`）。到这一步，没碰页面也知道该怎么打。

另一个办法是断点：调试器里在 `_0xboot()` 下断点，刷新后在「作用域」里直接看 `_0xa`，适合真实题目里不方便复制的情况。

### 3. 参数编码要先认出来

`/api/notes` 返回的 `id` 是 `"1"`…`"32"`，不是 `1`…`50` —— 这就是 **hex**。`0x32 = 50`，也就是最后一条（站主留言）。看到 `MQ==` / `32` / `a1b2` 这种，先判断是什么进制/编码，再决定怎么改，否则改了半天发现「参数根本不存在」。

### 4. 403 是边界，不是终点

站主留言给出目标 `/files/lab-files-0001/flag.txt`，访问返回 `403 AccessDenied`（XML 格式，模仿 S3 报错）。此时题目从「找信息」变成「过权限」。

遇到 401/403 先问三句：它凭什么判我有权？这个依据是谁写进去的？我能不能影响它？

- 不带 Cookie 也是 403 → 不是「登录就行」
- 文案写着 administrator → 判权大概率看角色字段
- `/api/me` 返回 `role: "guest"` → 系统里确实有「角色」这个概念

控制变量法验证：同一个号、只改一个输入、看结果变不变。

### 5. mass assignment：把服务端不该收的字段塞进去

注册只声明要 `username` / `password`，服务端却是这么写的：

```js
const user = Object.assign({}, body, { username, password: sha(password) });
```

整个请求体被合并进用户对象，只覆盖了用户名和密码 —— **`role` 原样保留**。于是注册时多送一个 `"role":"admin"`，账号就是管理员，`/api/me` 返回 `admin`，目标资源直接读出来。

识别信号：注册 / 更新资料 / 设置类接口 + 多传一个「不该由客户端决定」的字段。常用字段名：`role`、`roles`、`isAdmin`、`is_admin`、`admin`、`type`、`userType`、`level`、`permission`、`scope`、`status`、`verified`、`vip`。

排除法顺序（第 6 步没成功时）：换字段名 → 换值类型（`"admin"`/`true`/`1`）→ 换入口（更新资料接口）→ 退出重登（有的系统登录时才写角色）→ 换方向（IDOR / 令牌 / 路径绕过）。

### 6. 修复思路

字段白名单（只取 `username`、`password`，其余丢弃）、角色只由服务端赋值、返回用户信息时剥掉内部字段、对 `Object.assign` / `...body` 这类写法保持警惕。

## 踩坑记录

| 问题 | 原因 | 解决 |
|---|---|---|
| `node` 命令找不到 | Node 不在 PATH 上，DSH 工作区只有 `E:\DSH\node\node.exe`（本机另有 WorkBuddy 自带的一份） | 一律写绝对路径调用 |
| 起服务报 `listen EACCES 127.0.0.1:8123` | DSH 沙箱在 workspace-write 下禁止监听端口（不是端口被占） | 一次性用 `danger-full-access` 提权重跑同一条命令 |
| 手上这个 8123 端口「不像我起的」 | WorkBuddy 的 node 进程（PID 22660，`C:\Users\29381\.workbuddy\binaries\node\...`）在占，跑的是另一个同名靶场 | 自己这份换 8124，`server.js` 支持 `PORT` 环境变量 |
| 重新注册同名用户报 `username already exists` | 用户存在内存 `Map` 里，进程不重启就一直在 | 回归脚本用时间戳后缀造用户名；要干净状态就重启服务 |
| 前端改完没生效 | `public/app.js` 是构建产物，直接改会在下次构建被覆盖 | 改 `tools/app.body.js` 后跑 `node tools/build-app.js` |
| Python 输出中文在 PowerShell 里乱码 | 控制台编码不是 UTF-8 | `[Console]::OutputEncoding=[System.Text.UTF8Encoding]::new($false)` 或 `chcp 65001`；不影响断言结果 |
