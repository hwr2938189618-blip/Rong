# Windows [睡眠唤醒] 键鼠唤醒电脑的关闭与排查

> **日期**: 2026-11-03
> **标签**: #windows #电源管理 #powercfg #睡眠唤醒
> **状态**: 🟢 已整理

## 我要解决什么问题

睡觉/合盖时鼠标一动、键盘一压，电脑就醒了；想把「键盘鼠标唤醒」关掉，只留电源键（必要时留网卡 WOL）。顺便要能回答「刚才到底是谁把我叫醒的」。

## 核心概念

**唤醒源只有三类**，排查时按这三类逐一排除，不要只盯着设备管理器：

| 类型 | 例子 | 查法 |
|---|---|---|
| 固定功能 | 电源按钮、开合盖 | `powercfg /lastwake` |
| 设备（HID/USB/网卡） | 键盘、鼠标、触摸板、有线/无线网卡 | `powercfg /devicequery wake_armed` |
| 定时器 | RTC 唤醒（Windows 更新、计划任务） | `powercfg /waketimers`、`RTCWAKE` 设置 |

几条硬事实：

- 设备唤醒开关是**按设备**存在注册表里的，不在电源计划里，所以改电源计划没用；反过来，它也不随计划切换而变，一般重启后仍保持。
- `powercfg -devicequery wake_armed` 列出的名字就是 `-devicedisablewake` 要传的名字。同名设备会被自动加 `(001)` `(006)` 这种后缀，**后缀必须原样带上**。
- 除物理键鼠外，**虚拟 HID 设备也会成为唤醒源**。本例里就有 `GVINPUT`（某外挂工具）和 `TENCENTMYAPPSHIDBUS`（腾讯系应用的虚拟 HID）。
- 笔记本内置键盘常常走 PS/2（`ACPI\KBC8042`），它不出现在 `wake_armed` 里，说明内置键盘本来就不负责唤醒——真正让电脑醒的通常是外接 USB 键鼠接收器。

## 示例代码

### 1. 只读排查（普通权限即可）

```powershell
# 有没有唤醒历史、上一次是谁叫醒的
powercfg /lastwake

# 当前有权唤醒的设备（真正生效的）
powercfg /devicequery wake_armed

# 可以被设为唤醒的设备（候选池，含大量 HID 子设备）
powercfg /devicequery wake_programmable

# 唤醒定时器开关：0=禁用 1=启用 2=仅限重要
powercfg /q SCHEME_CURRENT SUB_SLEEP bd3b718a-0680-4d9d-8ab2-e1d2b4ac806d
```

### 2. 关掉键鼠唤醒（**必须管理员**）

先看 `wake_armed` 输出，把键盘/鼠标那几行原样抄下来，然后逐条执行：

```powershell
powercfg /devicedisablewake "HID Keyboard Device"
powercfg /devicedisablewake "HID Keyboard Device (006)"
powercfg /devicedisablewake "HID-compliant mouse (002)"
# …按实际清单继续
```

反向恢复（想重新允许唤醒时）：

```powershell
powercfg /deviceenablewake "HID-compliant mouse (002)"
```

彻底禁用唤醒定时器（可选，副作用是自动维护类任务不再唤醒电脑）：

```powershell
powercfg /setacvalueindex SCHEME_CURRENT SUB_SLEEP bd3b718a-0680-4d9d-8ab2-e1d2b4ac806d 0
powercfg /setdcvalueindex SCHEME_CURRENT SUB_SLEEP bd3b718a-0680-4d9d-8ab2-e1d2b4ac806d 0
powercfg /setactive SCHEME_CURRENT
```

### 3. 从普通会话提权执行（不用手动开管理员窗口）

```powershell
$exe = "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe"
Start-Process -FilePath $exe `
  -ArgumentList '-NoProfile','-ExecutionPolicy','Bypass','-File','<绝对路径>\wake-fix.ps1' `
  -Verb RunAs -PassThru -Wait
```

提权子进程的输出**不会回到当前控制台**，脚本里必须自己把结果 `Set-Content` 落盘，事后读日志确认。

## 本机实测（联想 83LT / Win11 26200 / S3 待机）

关闭前 `wake_armed`：3× HID Keyboard Device、2× HID-compliant mouse、有线和无线两块 Realtek 网卡。

按主人要求关掉全部键鼠、保留网卡后，复核只剩：

```
Realtek PCIe GbE Family Controller
Realtek 8922AE WiFi 7 PCI-E NIC
```

`RTCWAKE`（唤醒定时器）当时为 1（启用），主人选择保持不动。

## 踩坑记录

| 问题 | 原因 | 解决 |
|---|---|---|
| `powercfg /devicedisablewake` 报「此命令需要管理员权限」 | 写操作必须提升 | `Start-Process -Verb RunAs` 起提权子进程；提权后 `exit=0` 且无输出即成功 |
| 提权脚本的日志中文全变乱码（`鎵ц韬唤`） | PS 5.1 用 `-File` 执行**无 BOM 的 UTF-8** 脚本时按 ANSI(GBK) 解码 | 命令本身是 ASCII 所以照样生效；要中文正常就把脚本存成带 BOM 的 UTF-8 或纯 ASCII |
| `wake_armed` 里出现 `(006)` `(007)` | 多个设备同名，powercfg 自动加序号区分 | 传名字时把后缀原样带上，否则匹配不到 |
| 以为关了键鼠就没人能叫醒电脑 | 唤醒定时器（Windows 更新/计划任务）是独立通道 | 单独看 `RTCWAKE` 设置和 `powercfg /waketimers`（后者也要管理员） |
| 关闭后担心驱动更新会失效 | 设备唤醒位是设备属性，驱动重装可能被重置 | 复查命令就是 `powercfg /devicequery wake_armed`，一条命令确认 |
