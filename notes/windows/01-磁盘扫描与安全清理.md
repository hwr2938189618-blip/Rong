# Windows 磁盘扫描与安全清理

> **日期**: 2026-09-12
> **标签**: #Windows #磁盘清理 #PowerShell #文件管理 #踩坑
> **状态**: 🟢 已整理

## 我要解决什么问题

硬盘空间不够、文件杂乱重复，想清理又怕误删重要资料。学到的核心是：**清理的本质不是"删得狠"，而是"判断得准"**。

## 核心原则（五条铁律）

1. **先扫描、后动手** — 任何删除前必须完成只读扫描并产出清单
2. **决策点用选项呈现** — 不要让用户面对开放性问题
3. **删除前做占用检测** — 被占用的文件跳过并报告
4. **安全模式优先** — 未明确表态时，移动到归档区而非直接删除
   - ⚠️ **别依赖"回收站可还原"**：`Microsoft.VisualBasic.FileIO.FileSystem` 的 `SendToRecycleBin` 实测会报成功却没落进回收站 → **重要文件先复制到归档区，再删原件**
5. **资料类文件绝不当垃圾删** — 视频/文档/照片/安装包即使重复也是资料

## 关键概念

### 什么是"真重复"

判断两个文件是否重复，**不能只看文件名**。正确顺序是三重校验：

| 层级 | 方法 | 说明 |
|---|---|---|
| 1 | 文件名归一化 | 把 `报告 (1).docx` 归一成 `报告.docx` 再分组 |
| 2 | 比对字节数 | 大小不同，直接排除 |
| 3 | 内容哈希 | 前两层都过，再算哈希确证 |

**实测教训**：20 组同名文件里，只有 14 组内容真一致，**6 组其实是不同版次**——光看名字就删，会丢东西。

### 为什么大压缩包不能"看起来像重复就删"

一个 89.1 MB 的 zip 里，**只有 2.16 MB 内容和其他包重复**，删了会丢失 87 MB 独有内容。

→ **必须解压后逐项比对**，不能凭文件名和体积相似下判断。

### 递归扫描的隐形陷阱：符号链接

Windows 的 Junction（目录联接）会让扫描工具**跟随到其他盘**。

**实测事故**：用 Python `os.walk` 扫 E 盘回收站，它跟着 Junction 跑到了 D 盘，**把 D 盘的 29.9 GB 算成了 E 盘的内容**——统计严重虚高，还可能导致误删。

→ 统计时必须跳过重解析点（reparse point）。

## 示例代码

### 判断文件是否被占用

```powershell
$busy = $false
try {
    $fs = [System.IO.File]::Open($p, 'Open', 'ReadWrite', 'None')
    $fs.Close()
} catch { $busy = $true }
# $busy 为 true 说明被独占占用，删除前应跳过
```

比 `Get-Content` 可靠，能真实检测独占锁。

### 各盘可用空间

```powershell
Get-CimInstance Win32_LogicalDisk -Filter "DriveType=3" | ForEach-Object {
    "{0} {1} GB 可用 / {2} GB" -f $_.DeviceID,
        [math]::Round($_.FreeSpace/1GB,2), [math]::Round($_.Size/1GB,2)
}
```

### 删除 Junction（目录联接）的正确姿势

```powershell
# ❌ 错误：会连带删掉目标目录里的真实内容！
Remove-Item -Recurse $junctionPath

# ✅ 正确：只删除联接本身
[System.IO.Directory]::Delete($junctionPath, $false)
```

## 踩坑记录

| 问题 | 原因 | 解决 |
|---|---|---|
| 删除大目录脚本报错 exit code 1，以为失败了 | `Remove-Item -Recurse` 删完后有时仍返回非零码 | **可能已经删成功了**，务必复查实际状态，不要盲目重跑 |
| 清理完空间又变少 | 软件更新会自动重新灌入 GB 级缓存 | Temp 要定期复查；用"最近 60 分钟新/改的大文件"溯源 |
| 文件移动失败，以为是占用 | 其实是 ACL 显式拒绝 | 查权限：`BUILTIN\Users : Deny : Write, Delete` 需管理员权限 |
| 见到随机数字文件名 + 拒绝写删的 ACL，当成病毒 | 可能是正规厂商安装器的自我保护 | 先验数字签名再判断 |
| 用 `Get-Process` 被安全策略拦截 | 被识别为可疑可执行文件 | 改用 `Get-CimInstance Win32_Process` |
| 目录统计显示 0 | 同时传了 `-EA SilentlyContinue` 和 `-ErrorAction SilentlyContinue` | 不要重复传，注意复核结果 |
| `Remove-Item` 删 Junction 误删了目标内容 | Junction 被当作普通目录递归删除 | 用 `.NET Directory.Delete($p, $false)` |
| 以为用了 `SendToRecycleBin` 就能还原 | ⚠️ 实测：该参数**报告成功但没真进回收站**（查 `E:\$RECYCLE.BIN` 无对应项） | 重要文件先 `Copy-Item` 到归档区再删原件 |

## 迁移文件的经验

- **跨盘移动很快**：实测 9.3 GB 从 C 到 D 只要 7.6 秒（SSD）
- **迁移顺序**：先迁移（保住数据）→ 再删重复 → 最后建入口
- **目标盘已有同名文件时**：不要直接覆盖。算哈希 → 内容相同就删源；内容不同则**源文件改名带 `_下载版` 迁入**，保留两个版本让人来裁定
- **⭐ 同批资料不要拆散**：看起来孤立的文件往往是同批配套的一部分。按**时间戳聚类**找出整批，再问用户要迁哪些，而不是只抽走其中一个
