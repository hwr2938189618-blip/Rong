# 目录联接（Junction）：把程序数据搬出 C 盘，程序完全无感

> **日期**: 2026-09-14
> **标签**: #Windows #磁盘空间 #Junction #robocopy #数据迁移 #踩坑
> **状态**: 🟢 已整理

## 我要解决什么问题

C 盘空间紧张，但占地方的大头是**程序的配置和数据目录**（会话记录、缓存、运行时、密钥……），
它们默认都写在 `C:\Users\<你>` 下面。

直接搬到 D 盘？**程序就找不到它们了** —— 因为路径写死在配置里。

想找一个办法：**数据实际在 D 盘，但程序按原路径访问仍然一切正常**。

答案就是 **目录联接（Junction）**。

## 核心概念

### 目录联接是什么

一句话：**它长得像文件夹，其实是一张"传送门"**。

- 你在原路径看到的 `C:\Users\你\.codex` 还在
- 但它不再是真目录，而是一个 `ReparsePoint`（重解析点），指向 `D:\codex\.codex`
- 任何程序打开 `C:\Users\你\.codex\config.toml`，Windows 在**文件系统层**自动转发到 D 盘
- **对程序来说路径字符串一个字节都没变**

这带来两个直接好处：

1. **不用改任何配置** —— 程序里所有绝对路径照旧可用
2. **新数据自动落新盘** —— 以后程序新建的会话、日志、缓存全进 D 盘，C 盘不再增长

### 怎么区分"联接"和"快捷方式"

| | 快捷方式 (.lnk) | 目录联接 (Junction) |
|---|---|---|
| 谁能透明识别 | 只有资源管理器（好看） | **所有程序，包括命令行** |
| 命令行 `cd` 进去 | 打不开 | 正常进出 |
| 程序读写 | 报错 | 完全透明 |

所以搬程序数据必须用**联接**，用快捷方式是无效的。

### 判断一个路径是不是联接

```powershell
(Get-Item 'C:\Users\29381\.codex' -Force).Attributes
# 输出里出现 Directory, ReparsePoint → 它是联接
(Get-Item 'C:\Users\29381\.codex' -Force).Target
# 输出 → D:\codex\.codex
```

## 操作步骤

### 第 1 步：搬走真实文件

```powershell
robocopy "C:\Users\29381\.codex" "D:\codex\.codex" `
  /E /MOVE /COPY:DAT /DCOPY:DAT /R:1 /W:1 /NFL /NDL /NP /NJH /NJS
```

- `/E` 含空目录；**`/MOVE` 是关键** —— 复制成功后自动删除源文件
- `/COPY:DAT` 保留数据/属性/时间戳
- `/R:1 /W:1` 失败只重试 1 次、不干等
- `/NFL /NDL` 不刷屏列文件名（文件多时能快很多）

### 第 2 步：在原路径建联接

```powershell
New-Item -ItemType Junction -Path 'C:\Users\29381\.codex' -Target 'D:\codex\.codex'
```

**必须等第 1 步源目录真的为空之后再做**，否则联结会建在残留文件上。

### 第 3 步：验证（最重要的一步）

不要只看"文件夹在不在"，要**真的把程序跑起来**：

```bash
C:\Users\29381\AppData\Local\OpenAI\Codex\bin\<hash>\codex.exe --version
# → codex-cli 0.153.4   退出码 0  ✅
```

再回读几个关键文件确认大小正常：

```bash
head -12 "C:\Users\29381\.codex\config.toml"
```

## 踩坑记录

| 问题 | 原因 | 解决 |
|---|---|---|
| **⚠️ 千万别直接"删除"原路径** | 它现在是链接，**普通删除会连带删掉目标盘的真实数据** | 要撤只先确认属性含 `ReparsePoint`，再用 `rmdir` 删链接本身 |
| 搬上万个小文件极慢 | 跨盘复制每个文件都有开销 | 加 `/MT:16` 多线程；**robocopy 是幂等的，被中断直接重跑即可** |
| 任务跑到一半被掐断 | 前台命令有时限 | 放后台跑；中断不会损坏数据（它先复制、后删除） |
| `cmd /c mklink /J` 失败 | 这个环境的安全策略拦 cmd | 改用 PowerShell 原生的 `New-Item -ItemType Junction` |
| `robocopy` 退出码不是 0 | 它的返回码是**位掩码**（0~7 都算成功） | 判断成功率看"源是否空 + 目标是否完整"，别只看退出码 |
| 某些目录怎么都搬不动 | Windows 托管的应用包本体（如 `C:\Program Files\WindowsApps\...`） | **不要动**，它由系统托管，搬了会坏 |
| 搬的是程序"自带运行时" | 路径可能被程序写死，搬完可能反复重新下载 | 搬完**必须实测程序启动**；有风险就别搬（省下的空间未必值） |

## 安全性自查

搬完之后做一次审计，证明"只动了该动的"：

```powershell
# 1) 列出我新建的联接
Get-ChildItem 'C:\Users\29381' -Force -Directory |
  Where-Object { $_.Attributes -band [IO.FileAttributes]::ReparsePoint } |
  ForEach-Object { $_.FullName + '  ->  ' + ($_.Target -join ',') }

# 2) 系统关键目录的最后修改时间（应该都是很早的历史时间）
foreach ($p in 'C:\Windows','C:\Program Files','C:\Program Files (x86)') {
  (Get-Item $p -Force).LastWriteTime
}
```
