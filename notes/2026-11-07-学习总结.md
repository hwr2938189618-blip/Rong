# 2026-11-07 学习总结：额度恢复后的第一次真实回归，与一次「拒绝生成」

> 日期：2026-11-07

> 核心：**素材不足时停下来问，比生成一篇像样的日报更专业**

## 1. 背景

昨天把 ZCode 接进知识库（详见 [toolbox/11](toolbox/11-ZCode接入与知识库闭环.md)），收尾时撞上套餐限流：
`rate_limited` 且 `retryable=false`。当时只剩一件没验——**模型驱动 `rong-notes` 写笔记**。
脚本层早已反复跑通，缺的是模型那一环。

今天上午额度恢复，主人发起「记一篇笔记」，这一环补上了。

## 2. 技能第一次被真正调用

3 个工具调用，顺序本身就是证据：

| # | 调用 | 说明 |
|---|---|---|
| 1 | `Skill: rong-notes` | 描述命中 → 加载技能正文。**说明 frontmatter 的触发词写对了** |
| 2 | `Bash: git pull` + `git log --since=今天` | 不只拉镜像，还主动查「今天有没有人写过」 |
| 3 | `AskUserQuestion` | 问主题 |

注意工作区是 `draft-<uuid>` 而不是默认工作区——**技能照样被发现并加载**，
说明技能根是全用户级扫描，不依赖当前目录。

## 3. 它停下来的理由

原话大意：仓库今天零提交，本会话也没有任何学习内容，「每日总结要写当天全景 + 跨主题方法论，
我不能编造内容」。

这是 `AGENTS.md` 中「查不到就直说没记过，别假装笔记里写过」的**迁移版**：
那条规则原本约束"引用旧知识"，这里被自然地推广到了"生成新内容"。

一次空转的日报看着无害，实际会污染索引、让「最近更新」失真，
下一个人（或下一个 AI）会把它当成事实。代价是这一轮没有产出——**这个代价是对的**。

## 4. 同一件事的两个验证层

昨天额度断掉之后，office 插件是绕开模型验的：插件本质是本地 MCP 服务，
可以 stdio 直连握手，不需要任何模型（做法见 `toolbox/11` 的「office 插件实测」一节）。
今天补的是**模型层**。两层分开，才能说清"坏在哪"：

| 层 | 验什么 | 断了会怎样 |
|---|---|---|
| 脚本 / 服务层 | 脚本能否执行、MCP 能否握手、产物结构是否有效 | 无论谁驱动都失败 |
| 模型层 | 模型会不会读技能、选工具、判断该不该做 | 脚本没问题，但行为错 |

## 5. 方法论：今天的三条

1. **素材不足 = 拒绝生成**。写不出真东西时，问一句的成本远低于一篇假笔记的长期成本。
2. **验证要分层**。脚本层和模型层混在一起验，坏了只知道"整条不通"，不知道坏在哪一段。
3. **日报写增量，不重复主题笔记**。昨天的接入已经写进 `toolbox/11`，
   今天这页只记"补了什么"并指过去——日报不是主题笔记的目录。
